## Project Overview

Ghidra is the NSA's open-source software reverse engineering framework. It's a large multi-module Gradle project primarily written in Java (JDK 21), with native C++ components, SLEIGH processor specifications, and Python 3 debugger backends.

## Essential Build Commands

```bash
# First-time setup (fetch non-Maven deps, then prepare dev environment)
gradle -I gradle/support/fetchDependencies.gradle
gradle prepdev

# Build full release zip -> build/dist/
gradle buildGhidra

# Build native executables for current platform
gradle buildNatives

# Compile all SLEIGH processor specs (*.slaspec -> *.sla)
gradle sleighCompile

# Compile SLEIGH for a single processor (use Gradle project name, not path)
gradle :tricore:sleighCompile
gradle :V850:sleighCompile
gradle :x86:sleighCompile

# Clean compiled SLEIGH for a processor
gradle :V850:cleanSleigh
```

## Testing

```bash
# Unit tests (fast, minimal JVM context)
gradle unitTestReport

# Integration tests (slow, full Ghidra application context)
gradle integrationTestReport

# P-code emulator tests (processor instruction semantics validation)
gradle pcodeTestReport

# Run tests for a single module
gradle :Base:test
gradle :Base:integrationTest
```

Tests use JUnit 4. Unit tests live in `src/test/java/`, integration tests in `src/test.slow/java/`, and p-code emulator tests in `src/test.processors/java/`.

## Architecture

### Module Layout

```
Ghidra/
├── Framework/          # Core infrastructure (DB, Docking, Emulation, SoftwareModeling, etc.)
├── Features/           # Feature modules (Base, Decompiler, BSim, PDB, PyGhidra, etc.)
├── Processors/         # Processor language definitions (40+ architectures)
├── Debug/              # Debugger subsystem (Trace RMI protocol, agent connectors)
├── Extensions/         # Optional extensions
├── Test/               # Top-level test modules (IntegrationTest, TestResources)
└── Configurations/     # Build configurations
GPL/                    # GPL-licensed standalone native tools (must stay separate from Apache code)
```

### Per-Module Convention

Each Java module follows this source layout:
- `src/main/java/` — Production source
- `src/test/java/` — Unit tests
- `src/test.slow/java/` — Integration tests
- `src/test.processors/java/` — P-code emulator tests
- `data/languages/` — SLEIGH files (processor modules)
- `data/pcodetests/` — Pre-compiled ELF test binaries (processor modules)

### Build System

Gradle with mix-in scripts in `gradle/`. Key scripts:
- `gradle/processorProject.gradle` — Defines `sleighCompile` and `cleanSleigh` tasks
- `gradle/javaTestProject.gradle` — Wires unit/integration test tasks
- `gradle/root/distribution.gradle` — `buildGhidra`, `assembleAll`

### SLEIGH (Processor Specifications)

SLEIGH is Ghidra's language for defining instruction set semantics. Processor modules under `Ghidra/Processors/<arch>/data/languages/` contain:
- `*.slaspec` — Top-level spec (includes `.sinc` files, defines endianness/alignment)
- `*.sinc` — Instruction definitions with p-code semantics
- `*.ldefs` — Language definitions (variants, compiler specs)
- `*.cspec` — Calling conventions
- `*.pspec` — Processor-specific register/memory definitions
- `*.sla` — Compiled binary output (generated, do not edit)

The SLEIGH compiler lives in `Ghidra/Framework/SoftwareModeling` (`ghidra.pcodeCPort.slgh_compile.SleighCompile`). To find a processor's Gradle project name: `gradle projects | grep <name>`.

### P-code Emulator Tests

Test classes extend `ProcessorEmulatorTestAdapter` from `Ghidra/Features/Base`. They load pre-compiled ELF binaries from `data/pcodetests/` and verify instruction semantics via emulation. Pattern:
- Class specifies `LANGUAGE_ID` and `COMPILER_SPEC_ID`
- `getProcessorDesignator()` returns a string matching the `.out` filename prefix
- Static `suite()` method required

### Debugger

Uses Python 3 + Protobuf-based TCP (Trace RMI protocol). Connector agents live in `Ghidra/Debug/Debugger-agent-{gdb,lldb,dbgeng,drgn,x64dbg}/` with Python code in `src/main/py/`. After Python changes: `gradle assemblePyPackage`.

## Key Gotchas

- Gradle project names for processors are short (`:V850`, `:tricore`, `:x86`), not full paths
- GPL-licensed code must live in the top-level `GPL/` directory, not under `Ghidra/`
- On Linux, set `export LC_MESSAGES=en_US.UTF-8` if native toolchain detection fails
- The build rejects 32-bit JVMs
- `.sla` files are gitignored build artifacts; they are regenerated by `gradle sleighCompile`
- When testing modified SLEIGH locally against an installed Ghidra, copy the `.sla` to `<Ghidra install>/Ghidra/Processors/<arch>/data/languages/` and restart Ghidra
